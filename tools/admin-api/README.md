# Кабинет администратора

Адрес: https://eslavia.ru/admin/ (вход по паролю, страница закрыта от поисковиков).

Сохранение товара одним коммитом обновляет data/products.json, data/categories.json,
фото товара, оптовый прайс (PDF), каталог Mini App и пост в канале @eslavia_opt.

Бэкенд: Yandex Cloud, каталог `eslavia`: функция `eslavia-admin-api`, API Gateway
`eslavia-admin-gw`, секреты в Lockbox `eslavia-admin`. Исходники функции: tools/admin-api/.
После правок в `tools/admin-api/` нужна новая версия функции в YC (см. `AGENT_TODO.md` в корне, если файл есть).

Служебные данные: data/tg-posts.json (связь товар → сообщения в канале),
data/price-thumbs/ (миниатюры для прайса).

Таблица Excel: «Скачать таблицу» (/export) выгружает весь каталог, «Загрузить таблицу» показывает
разницу (/import-preview) и применяет её одним коммитом (/import-apply). Строки, которых нет в таблице,
удаляются только после отдельного подтверждения. Если в столбце «Категория» или «Доп. категории»
написано название, которого нет в каталоге, проверка не считает это ошибкой: кабинет показывает
список и применяет его только после отметки «Добавить эти категории». «Скачать прайс» (/pdf) отдаёт PDF из репозитория.

Telegram: из Yandex Cloud Functions api.telegram.org недоступен (соединение режется по пути, проверено
17.11.2026). Поэтому перед коммитом функция проверяет связь (getMe), а неотправленные обновления постов
кладёт в data/tg-queue.json тем же коммитом. Отправить очередь: кнопка «Отправить ещё раз» в кабинете
(сработает, если связь появится) или с машины, где Telegram открывается:
`GITHUB_TOKEN=... TG_TOKEN_FILE=~/.secrets/eslavia_opt_bot.token python tools/admin-api/flush_tg_queue.py`.

## Пустые посты и их повторное использование

Telegram не даёт боту удалять сообщения старше 48 часов. Если пост удалённой модели удалить нельзя,
его фото заменяются заглушкой, подпись убирается, а пост записывается в `data/tg-posts.json` → `blankPosts`.
Кабинет показывает напоминание удалить такие посты вручную (кнопка «Я удалила пост» → `/blank-done`).
Новая модель сама занимает пустой пост (сначала той же категории, иначе самый старый); если удаление и
добавление попали в один запуск очереди, пост сразу переходит новой модели без заглушки.

## Журнал изменений

Каждое действие кабинета дописывает записи в `data/admin-log.json` тем же коммитом, что и само изменение
(последние 1000 записей): добавление и правка модели с разницей по полям, удаление, импорт из Excel
(итог и запись на каждую модель), отметка «Я удалила пост». `flush_tg_queue.py` (GitHub Actions) пишет туда же,
что сделано в канале: пост обновлён, создан, переиспользован, очищен, навигация перевыложена.
В записи хранится `base` — коммит, на котором сделано изменение; `/log` по истории файла находит sha самого коммита.

`GET /log?model=&action=&offset=&limit=` — записи от новых к старым; `action`: edit, add, delete, import, tg.
