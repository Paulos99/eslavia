# MASTER PROMPT — РАЗРАБОТКА САЙТА-КАТАЛОГА «ТАИСИЯ»

## Роль

Ты — ведущий AI-архитектор и технический руководитель проекта.

Твоя задача — спроектировать и реализовать новый современный одностраничный сайт-каталог для компании «Таисия», полностью заменив текущий сайт:

**https://taisiy.ru/**

Работа выполняется в Cursor.

Проект должен быть выполнен профессионально: с предварительным исследованием, декомпозицией задач, параллельной работой специализированных субагентов, контролем качества и финальным аудитом.

---

# 0. ГЛАВНОЕ ПРАВИЛО ПРОЕКТА

НЕ начинай сразу писать интерфейс.

Сначала:

1. изучи текущий сайт;
2. полностью собери его контент;
3. сформируй структурированную базу номенклатуры;
4. проанализируй UX/UI текущего сайта;
5. сформируй новую информационную архитектуру;
6. разработай визуальную концепцию;
7. разбей работу между субагентами;
8. только после этого начинай реализацию.

Текущий сайт является **информационной базой проекта**, а не визуальным референсом.

Новый сайт должен сохранить актуальное содержание и ассортимент, но получить полностью новую UX/UI-концепцию.

# 1. ЦЕЛЬ ПРОЕКТА

Создать современный одностраничный сайт-каталог женского трикотажа.

Основные задачи сайта:

### Для розничного покупателя

Показать:

- ассортимент;
- категории;
- фотографии;
- названия моделей;
- артикулы;
- розничные цены;
- размеры;
- цвета;
- материалы;
- характеристики;
- описание товаров.

### Для оптового покупателя

Создать понятный путь:

**сайт → каталог → интерес к ассортименту → запрос оптового прайса → контакт**

На сайте должна быть форма:

**«Получить оптовый прайс»**

Пользователь оставляет контактные данные и получает доступ к актуальному оптовому прайсу.

Новый сайт НЕ является полноценным интернет-магазином.

Не реализовывать:

- корзину;
- онлайн-оплату;
- личный кабинет;
- регистрацию пользователей;

- избранное;

- оформление заказа;
- сложную e-commerce систему.

Если текущий сайт содержит такие функции — они являются частью старой платформы и НЕ должны переноситься в новый проект.

# 4. СОЗДАТЬ LOCAL CONTENT DATABASE

До создания UI сформируй локальную структурированную базу данных проекта.

Например:

```text
/data
  /products
    products.json
  /categories
    categories.json
  company.json
  contacts.json
  size-guide.json
```

Каждый товар должен иметь структурированный объект примерно такого вида:

```json
{
  "id": "mtk-104",
  "article": "МТК-104",
  "name": "Костюм МТК-104",
  "category": "Костюмы",
  "priceRetail": 670,
  "priceWholesale": 550,
  "sizes": ["44", "46", "48", "50", "52", "54"],
  "colors": [],
  "material": "",
  "description": "",
  "images": []
}
```

Не выдумывай отсутствующие данные.

Если на старом сайте характеристика отсутствует:

```text
null
```

или пустое значение.

Никогда не придумывай материал, цвет, состав или описание.

# 5. ПОЛНЫЙ ПЕРЕНОС ИЗОБРАЖЕНИЙ

Для каждого товара необходимо определить изображения, используемые на текущем сайте.

Изображения должны быть:

- скачаны;
- сохранены локально;
- связаны с соответствующим товаром;
- переименованы системно;
- оптимизированы для web;
- сохранены без визуальной потери качества.

Предпочтительная структура:

```text
/public
  /images
    /products
      /mtk-104
        01.webp
        02.webp
        03.webp
```

Если исходные изображения доступны в хорошем качестве — используй их.

Не используй скриншоты страниц вместо оригинальных изображений.

Не используй placeholder, если реальное изображение удалось получить.

---

# 6. КОНТЕНТ НЕ ДОЛЖЕН БЫТЬ ЗАШИТ В КОМПОНЕНТЫ

НЕ делать:

```jsx
<h3>Костюм МТК-104</h3>
<p>670 ₽</p>
```

непосредственно в каждом компоненте.

Вместо этого:

```jsx
products.map(product => ...)
```

Контент должен находиться в структурированной базе данных.

Это позволит в будущем менять:

- цены;
- названия;
- фотографии;
- размеры;
- описания;

без переписывания компонентов.

# 28. АНИМАЦИИ

Анимации должны быть функциональными и спокойными.

НЕ делать:

- постоянные floating animations;
- сложный parallax;
- сложные 3D;
- flashy effects;
- анимацию каждого элемента.

Использовать:

### Page load

Лёгкое появление hero:

```text
opacity 0 → 1
transform translateY(20px) → 0
```

Duration:

**600–800ms**

### Scroll reveal

Секции:

```text
opacity
translateY
```

Duration:

**500–700ms**

### Product hover

Изображение:

```text
scale(1.03)
```

Duration:

**350ms**

### Modal

Fade + translate.

### Navigation

Smooth scroll.
